# Scoped Workshop replacement on OpenClaw main

Candidate baseline: `openclaw/openclaw@dad4fc1a037821f2e503df81fe43171bf61af656` (2026-11-06), with [#191205](https://github.com/openclaw/openclaw/pull/191205) and `tests/memory-scope/native-workshop-gateway/backport-sandbox-learn.py` applied. This replaces the bundled `skill-workshop` plugin for admitted DingTalk turns. Stock main's `/learn` rejects all sandboxed turns before reaching plugin tools; the second host patch lets only explicitly compatible contributions continue through normal tool policy. It is a development candidate until real WSL acceptance below passes.

The DingTalk connector authenticates the incoming tenant, sender, bot account and conversation, and owns the revocable scope data service. `dingtalk-scoped-workshop` registers `skill_workshop` and the native `/learn` contribution. It uses the upstream Workshop scheduler and OpenClaw `runForkedTurn`; OpenClaw owns transcript anchoring, model, work admission, sandbox policy and stop lifecycle. The connector no longer schedules reviews.

The plugin's only storage route is the connector's registered scope service. The registering module keeps the grant validator and Workshop store; other loader copies invoke bound methods rather than interpreting a grant in their own module. The connector unregisters that service on disposal/stop. Background forks require the host's `internal_system/session_fork` origin, the exact plugin owner and source session, an active source lease and live invocation. A new sender turn revokes the old lease; pending review candidates refresh to the latest completed turn. No model parameter chooses an identity or path.

To select the replacement, migrate pre-plugin Workshop policy first (`meta.migrations.skillWorkshopPlugin: true` after checking the historical policy, or use OpenClaw Doctor), explicitly disable bundled `skill-workshop`, and install/enable the replacement as its own package directory. Without the migration marker, current main ignores the disabled entry and loads the bundled tool. The target agent must allow `skill_workshop` in both its normal and sandbox tool policies. The plugin also needs `allowConversationAccess` and `allowPromptModification` hooks. Its `autonomous.mode` defaults to `off`; set `auto` to use the inherited 10-iteration/30-second-idle trigger. Do not register an agent-wide learned-skill discovery directory. The current scope's index is projected to the active model; the model reads a selected skill through `skill_workshop view`.

The registered Workshop storage preserves the PR18 private/group namespaces and revision history. The replacement supports list, view, create, patch, supporting-file write/remove, archive and restore of the latest change. It does not yet claim native CLI/UI library integration, propose drafts, version-ID restore, or native global maintenance. Those would require scope-aware owner interfaces rather than reading the private storage directly.

The `skill_workshop` tool has no mandatory save. The upstream scheduler can ask a separate model to review completed work; the model may abstain. Its review prompt explicitly carries the initiating user's restriction against learning, while quoted file/tool content remains evidence. This is model behavior guidance, not a formal natural-language consent parser. Verify real model outcomes separately from deterministic Gateway fixtures.

Validation required before publication: complete targeted unit and type tests; built-package canonical-module check; isolated Gateway with actual `dispatch_action`, original handler, native fork and one positive/negative review; sandbox-enabled Gateway using PR191205's prepared-sandbox projection; real WSL two private users plus same-group shared learned procedures; `/learn` create/view/undo; request-scoped no-learning; DWS and normal attachments; restart and source revocation. Keep PR19 draft until actual results and CI match its head.
