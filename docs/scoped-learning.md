# Scoped learning on the shared DingTalk agent

Status: PR19 candidate on OpenClaw main `dad4fc1a037821f2e503df81fe43171bf61af656`. Current WSL remains on the previous implementation until the replacement passes real-model and sandbox acceptance. Historical PR18 evidence is retained in [validation history](scoped-learning-validation.md).

The Connector authenticates tenant, bot account, exact sender and group ID. It supplies a revocable private/group storage capability and the `scoped_memory` tool. The independent [scoped Workshop plugin](../plugins/scoped-workshop/README.md) owns `skill_workshop`, `/learn` guidance and the official Workshop review scheduler. OpenClaw owns the model run, anchored transcript, fork, cancellation, sandbox and tool policy. The Connector does not start a review.

Private chats address `(tenant, account, agent, sender)`; group chats address `(tenant, account, agent, conversation)`. Different groups and private chats are separate. Group members share the group's learned procedure; the current sender is recorded as actor. Identity never comes from model arguments, filenames or parsing the session key.

The plugin uses the official `runForkedTurn` with its own registered tool. A completed source turn captures a scope lease from the Connector. The fork must have the host's internal origin, this plugin's owner ID, the exact source session and a live invocation. The Connector's registered module performs storage calls itself, so another bundled module cannot mistake a valid grant for an unknown one. New input, reset, permission changes, plugin reload and Gateway stop revoke stale work. The scheduler may run a review after sufficient model work; the reviewer may choose no write. Explicit user restrictions against learning are carried in review guidance; natural-language understanding still needs live-model validation.

The stored bundles retain PR18's private directories, versions, CAS checks and latest-change undo. Current actions are `list`, `view`, `create`, `patch`, `write_file`, `remove_file`, `archive` and `restore`. The implementation does not claim upstream Workshop UI/CLI library, propose drafts, version-ID restore or agent-wide maintenance. No private Workshop root is mounted into a script sandbox. Public installed skills are outside this learning scope.

Install the replacement plugin alongside a compatible Connector and disable the bundled `skill-workshop` explicitly. Permit `skill_workshop` for the target agent and sandbox, grant both plugins their declared hook permissions, and choose `autonomous.mode: auto` only when automatic reviews are wanted. `off` still allows a user to ask for a procedure explicitly. Exact configuration and unsupported features are in the [plugin README](../plugins/scoped-workshop/README.md); the Connector [scope setup](scoped-setup.md) previews memory-related Gateway changes separately.

Validation before a release: `npm test`, `npm run test:workshop`, both strict TS configs, Connector and plugin builds, the [synthetic Gateway fixture](../tests/memory-scope/native-workshop-gateway/run.py) on the target host, then two real users and a group on WSL with the actual model. Synthetic provider responses prove wiring and storage but not that a real model will honor every “do not learn” request. Sandbox and public read-only mounts are OpenClaw settings, and the unmerged [PR191205](https://github.com/openclaw/openclaw/pull/191205) projection must be present before claiming its sandbox fact is correct on the pinned main baseline.
